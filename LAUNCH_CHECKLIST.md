# KevinBrodzinski.com — Public Launch Checklist

## Required before announcing the site
- [ ] Point `kevinbrodzinski.me` DNS to the chosen static host.
- [ ] Enable HTTPS and confirm a valid certificate.
- [ ] Redirect `www.kevinbrodzinski.me` permanently to `https://kevinbrodzinski.me/`.
- [ ] Upload this directory with `index.html` at the web root.
- [ ] Confirm `/research/` and `/patents/` return HTTP 200.
- [ ] Confirm the 90-second hiring view opens from `/?hiring=1`.
- [ ] Test resume download on desktop and mobile.
- [ ] Test email and LinkedIn links.
- [ ] Test the Academia profile and representative paper links.
- [ ] Confirm Open Graph previews for home, research, and patents.
- [ ] Submit `/sitemap.xml` to the search engine tooling you use.

## Job-application smoke test
A hiring manager should be able to answer these in under 90 seconds:
1. What does Kevin build?
2. What is he building now?
3. Can he operate across research, product, architecture, and enterprise execution?
4. What research is public?
5. What invention/IP architecture exists?
6. How do I contact him or download his resume?

## Public claim discipline
- Research maturity labels must remain visible.
- Patent pages must distinguish provisional/application material from issued patents.
- Do not publish an exact total filing count until the authoritative filing ledger is receipt-verified.
- Keep speculative physical/ontological interpretations separated from production architecture.

## IP / confidentiality

- [x] IP-safe public disclosure pass completed across Home, Research, and Patents.
- [x] Unpublished patent titles, mechanism archives, application numbers, exact filing chronology, source code, parameters, and continuation strategy withheld.
- [ ] Patent counsel final review before public launch if foreign rights, pending filings, or trade-secret treatment are strategically material.
